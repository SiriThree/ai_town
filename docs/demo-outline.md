# 3–5 分钟本人演示提纲（V12，建议 4 分 40 秒）

这是待录制提纲，**不是已完成的视频**。替换早期两居民版本的讲解稿；历史验收记录不改写。当前玩法与启动入口见[根 README](../README.md)。

录制前：使用专用演示世界和支持 WebGL 的浏览器，准备当前生产构建；保留主存档，关闭无关窗口，隐藏密钥、数据库连接串和私人聊天。主演示先用无密钥模式排练。真实模型片段只在配置齐备且获授权后进行一次必要请求；如未获授权，就明确展示 Fallback，并引用历史真实调用证据，不能把替身称为 Qwen。

| 时间 | 实际操作与画面 | 本人讲解要点 |
|---|---|---|
| 0:00–0:30 | 展示正常游玩镜头、全景、六名居民；点阿晴和阿宁档案 | “这是一个共享世界、私聊隔离的小镇。六名居民和十二栋可进入建筑；人物行动不是固定动画。” |
| 0:30–1:10 | 开始自动运行，观察居民沿路行动、进门或工作，然后暂停 | 后台每现实秒结算两游戏分钟，保存行动进度；规则按需求、性格和合法条件决策。前端只表现真实路径；无人访问不离线补算。不要沿用早期五秒一步的口径。 |
| 1:10–1:40 | 展示居民饥饿值，送食物后再次查看；说明控制变量测试 | 实际减少饥饿值，后续决策能读取变化。不会宣称所有自然状态都立即改变动作；展示 world.test.ts 中控制条件的证据。 |
| 1:40–2:20 | WASD 靠近居民，按 E，问“你现在在做什么？”；查看头顶气泡 | 真实状态进入模型上下文，回答不能代替后台执行。若使用获授权真实服务，诊断中核对 source；否则明确本段是 Fallback。正常玩家 UI 不常驻技术标签。 |
| 2:20–2:50 | 在独立无密钥实例发送同样问题，打开一次诊断，再关闭 | 无密钥也按人格和状态回答。超时/服务错误由本地故障测试验证，Mock 不是外部模型。展示已有错误证据，不现场反复付费制造故障。 |
| 2:50–3:25 | 同一访客问姓名；展示已确认的咖啡馆时间或公告板聚会结果 | 姓名有来源、按访客隔离；后台确认约定才承诺，到达和会面分开。公告参加者与缺席者有不同真实记录。使用实际已有存档，不伪造现场发生过全部过程。 |
| 3:25–3:55 | 暂停后刷新；正常重启专用演示 Web 服务，核对时间、状态 | PostgreSQL 保留世界与私聊；行锁和版本检查避免覆盖。双标签不重复加速；不是浏览器 localStorage 存世界。不要重启别人服务或清库。 |
| 3:55–4:25 | 展示 V2 原 Modal 与 V2.1 气泡证据，回到当前页面 | “我审查 AI 生成的大 Modal，认为不符合小镇体验，提出轻输入和场景气泡，限定不改后台，由 AI 修改后继续验收。我没有手工编辑这部分源码。” |
| 4:25–4:40 | 展示 README 与核心模块位置 | world.ts 决策、store.ts 事务、chat-context.ts 事实、chat-model.ts 模型边界。说明实际线上 URL/有效期；尚未发布就诚实说本地演示。 |

录制不必在 5 分钟内等待整场聚会；完整 V12 连续流程可作为附录，见[V12 验证记录](v12-validation.md)。若剪辑等待时间，应标注跳时，不能把预先完成的活动伪装成当前即时结果。正式视频包含本人声音与实际操作，已有无讲解测试录屏不能代替它。

现场改代码可选择调整 world.ts 的 FOOD_AMOUNT，解释数值边界和后续决策影响，同步修改相关断言并运行 `npx vitest run tests/world.test.ts tests/world-controls.test.ts`。先在隔离数据排练，不改正式世界来制造结果。本人应能解释改动与失败原因，不能只照读 AI 文档。
