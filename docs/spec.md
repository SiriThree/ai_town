## 2. 我们选择的玩法和实现方案

### 玩法与演示重点

**本轮收敛：**在已完成的手动世界闭环与真实 AI 场景对话上，只增加送食物与固定速度自动运行。邀请、其他玩法和地图重做留待后续。应用目录 `web/`；Next.js + TypeScript，PixiJS 绘制场景，React/HTML 实现窗口。

**参考决定：**[SKYCity 评估](reuse-assessment.md)保留为历史证据，仅参考决策/执行分离和恢复验证；玩家聊天缺失、Fake 脚本路径和经济/反思耦合使整仓收缩超出本项目范围。本地 `my_ai_town-main.zip`（实际根目录经检查为 `my_ai_town-main/`）是主要视觉和交互参考，晨露村概念图为辅助。定向查看 README、全景/对话/日志截图，以及居民选择、档案、日志主题、地图分层源码；采用连续道路、明显屋顶/立面/入口、独立人物与浅纸棕框窗口。其根许可证尚未发布，不复用其自有代码或素材；本轮自行绘制简化像素场景，细节精度尚不等同参考作品。

玩家作为观察者，通过 NPC 的需求变化、行动理由和干预后的行为变化理解小镇。首版不设输赢。

| 对象 | 首版选择 |
| --- | --- |
| NPC 阿晴 | 外向、喜欢社交；基本需求满足时偏向去广场聊天 |
| NPC 阿宁 | 安静、喜欢阅读；基本需求满足时偏向去广场阅读 |
| 地点 | 住宅（休息）、咖啡馆（进食）、广场（社交或阅读） |
| 可见信息 | 性格、地点、饥饿、精力、心情、当前行动、最近一次决策理由 |
| 玩家操作 | 查看 NPC、文本对话、提供食物降低饥饿；邀请社交未实现 |
| 页面 | 三个地点的简单地图、NPC 详情、对话区、事件记录、推进一步和自动运行开关 |

状态数值限制在 0–100。每一步先更新需求，再按饥饿、精力和性格偏好选择动作；需求紧急时优先进食或休息。当前没有邀请机制。用少量显式规则和固定的平局处理顺序，返回动作及可解释理由。同样的世界输入得到同样的规则结果，但不同状态会产生不同行动，不能按时间轮播脚本。

需要换地点时本步执行移动，留在相应地点后才能进食、休息、社交或阅读。执行器校验动作和地点，更新状态并记录事件；详情和日志展示真实结果。NPC 根据当前需求自行选择动作；手动点击或自动唤醒复用同一推进函数。自动模式每 5 秒到期，浏览器每秒最多一次唤醒且等待上次请求完成；关闭全部页面后不再推进，运行开关仍保留，返回时最多补一步。

### 技术、API 与首条链路

选择 Next.js + TypeScript，前后端同仓库；用 Route Handlers 提供明确 HTTP API，服务端运行规则与存储逻辑。具体依赖版本在实施时选定并锁定。页面只展示 API 返回的已保存状态。

**优先链路：读取世界 → 规则决策 → 执行动作 → 保存 → 返回页面展示。** 首阶段就落数据库，不用仅内存或浏览器存储冒充存档。

| 拟定接口 | 职责 |
| --- | --- |
| `GET /api/world` | 只读取世界；未初始化返回 404，不隐式写入 |
| `POST /api/world/init` | 独立的首次初始化入口；已有世界返回原存档，不重置 |
| `POST /api/world/tick` | 推进一步，返回已提交世界、动作与理由 |
| `POST /api/world/run` | 保存运行/暂停状态；开始设定下一次到期 |
| `POST /api/world/wake` | 在世界行锁内按数据库时钟判断到期，至多推进一次 |
| `POST /api/world/interventions` | 仅校验并执行送食物，保存状态与事件后返回世界 |
| `POST /api/npcs/:id/chat` | 结合人设、状态和少量最近对话，返回真实 AI 或降级回复及模式 |
| `GET /api/npcs/:id/chat` | 获取当前世界该居民保留的最近 20 轮玩家对话 |

规则函数、动作执行函数、存储函数、AI 调用函数保持清晰边界即可，不建设通用 Agent 框架。规则决定世界动作，AI 首版只负责对话，不直接改数据库，也不从任意模型文本执行命令。

### 本地和线上恢复

- 统一使用 PostgreSQL：本地使用本项目独立 Docker 容器、端口和卷；线上拟使用托管数据库，以 `DATABASE_URL` 切换。2026-10-09 重新检查：启动已安装的 Docker Desktop 后 Engine 可用，存在 postgres:17 缓存镜像；不使用其他项目数据库。线上连接/恢复尚待后续验证。
- 小规模首版按世界保存 JSON 快照，附 `worldId`、`schemaVersion`、`revision` 和更新时间；快照包含时钟、NPC 状态、最近事件及可选运行时钟；对话独立存入 town_chats。不做完整事件溯源。
- 本轮是仅用于本地演示的一个世界，服务端 `WORLD_ID` 标识；刷新或后台重启均读取同一 PostgreSQL 行。居民选中状态放在 URL，只保存界面选择，不保存世界。公开部署前再加入访客会话隔离；本轮不宣称多访客隔离已完成。
- 一次 tick 的两个 NPC 更新与事件一起原子提交；事务行锁及 expectedRevision 校验，过期写入返回 409 并重读。前端同步请求锁+禁用按钮，重复旧版本请求只会有一次成功；不额外搭建请求队列或通用幂等框架。保存失败显示错误，不显示未提交结果；不兼容存档明确报错。
- 限制近期事件和对话条数，避免快照持续膨胀。数据库备份负责数据库故障恢复，频率和保留期随供应商确定；应用重启恢复与数据库灾难恢复分别说明。

### 真实 AI 与降级

第二阶段采用服务端 HTTP 的 OpenAI-compatible Chat Completions 适配器，无新增 SDK。配置 `AI_API_KEY / AI_BASE_URL / AI_MODEL`；另以 `AI_ENABLED=true` 显式启用，缺配置或未启用直接用本地规则。用户已提供本项目模型配置，已放入忽略提交的 `.env.local`；已按用户授权启用并完成一次真实调用验收，见下方启用记录；V3 自动化只使用禁用模式或本机替身。

每条输入 1–500 字符；上下文只取当前居民身份/性格、地点、行动、需求、本人最近 3 条事件与 4 轮对话。默认模型超时 8 秒（可配置 0.1–10 秒），无自动重试；异常、超时、HTTP 错误、空/坏回复都回退到有个人差异的本地回复。返回 `reply / source: ai|fallback / reason`，页面逐条标记；本机测试替身另明确标注，不算真实模型验收。

对话存入同一 PostgreSQL 的独立 `town_chats` 小表，按 `world_id + npc_id` 隔离，每人最多 20 轮；记录发送时世界版本和游戏时间。会话只读世界，不更新 `town_worlds`，没有模型工具或动作执行权限。每人数据库会话锁拒绝并发聊天覆盖，不锁住世界推进，不建设队列。模型仍可能生成不符合事实的话，不能把提示约束当成事实正确性的证明。

密钥只在服务端环境变量中读取；诊断只记录来源、错误类别、耗时及 HTTP 状态，不记录密钥、完整 URL、消息或错误正文。数据库失败不是模型失败，返回错误而不冒充已保存回复。V2.1 改为场景下沿输入区，阻止输入事件冒泡；居民头顶显示已保存的回复，历史按需展开。

调用设置超时、输入长度和输出长度限制；无密钥、超时、限流、服务错误或空回复时回退到规则回复，界面明确标记“AI”或“降级”及简短原因。公共演示限制会话请求频率和并发。实际接入验收必须有一次真实成功调用，Mock 测试不能替代；供应商失败不阻断世界推进。存储故障则明确报错，不能伪装成正常存档。
