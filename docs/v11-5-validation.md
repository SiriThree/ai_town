## 最小修复与调用链

签名 Cookie → 服务端 visitorId → `chat` → `privateConversationState` 单条 SQL → `buildMessages` → 现有模型适配 → `checkChatFacts` → 原私聊 JSONB 保存。模型等待没有世界事务锁。

- 同一 MVCC 快照内按 world_id + npc_id + visitor_id 读取世界、近期约定，以及最多6条重要约定来源。先按“昨天/前天/今天/第N天”的**世界日**筛选，再优先已履行、取消/失败、进行中记录，不被新近拒绝和寒暄挤走。日期数值有边界保护。本轮语义范围是既有咖啡馆约定，未开发任意主题检索。
- 使用已有 `town_invitations.payload` 与持久化 `response`，保留真实约定行ID、原确认turnId、事件minute、实际结果；分别提取邀请确认、实际到达、取消、失败、拒绝和推迟。取消请求回执不算第二次邀请，拒绝/推迟不算接受，未来或不一致时间不作为已发生证据。事件按时间排列，同一约定同时接受/到达时先确认再到达。ID明确来自约定表，没有伪造新的公共世界事件ID。
- Prompt 将 `currentFacts`（场景、坐标、行动、工作已完成步骤/实际执行、有效约定）、`pastCommitments`、`importantPlayerEvents`、普通近期对白分开；公共近期事件也携带原ID。模型必须区分过去与现在、任务与执行、NPC到达与玩家到场。
- “还记得我们的约定吗”现在使用自然模型回复及检索证据；纯状态查询继续确定性返回，邀请/取消仍走原确认事务。无密钥/失败时也能利用同一份重要经历，不退化为只谈最近寒暄。
- 窄范围事实保护：当前任务进度0却明确说一半/收尾，或已有邀请证据却声称之前只打招呼，改为真实本地回复，标记 `source=fallback, reason=fact_conflict`。合法自然对白原样通过，未把所有回复模板化。
- 原模型文本保留于本人 `ChatTurn.factCheck.originalReply`，同时保存冲突code及来源ID；原历史API可查询，普通气泡展示修正后的对白。该字段是私有JSONB的可选字段，旧记录不需迁移；没有写入公共事件、NPC公共记忆或其他访客历史。现有诊断来源标签能显示事实冲突降级；原始冲突详情目前通过私有历史API/证据查看，没有新增诊断面板。
